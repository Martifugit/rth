# Vision

The top of the GDD: what R'th is, and the tests every other page is held to. Written first and kept
short, because everything below it is judged against it. The pages, and what each holds:

| Page | Holds | Status |
| --- | --- | --- |
| `overview.md` | The game in one paragraph (what it plays like, looks like, where it is set, who it is for), then a player's experience in the second person ("You wake on a bier under a bell tower..."), then the handful of features that make it R'th rather than any RuneScape-like. | to write |
| `pillars.md` | **Three to five pillars**: the experiences the game delivers, each specific enough to rule real ideas out, each with an example of something it rules out. Then **non-goals**: the tempting things R'th deliberately doesn't do (PvP, anti-cheat, sharding, an opening cutscene...). | to write; **the owner's** |
| `audience-and-scope.md` | Who plays (an invited group of friends, at most about 200), how they play together, and what two people can make: the scope that every proposal is weighed against. | to write |
| `loops.md` | The loops a player lives in, each as a diagram: the moment-to-moment (a fight, a gathering trip), the session (go out, fill the pack, come back, bank, make), and the long run (tiers, quests, achievements, records). | to write |
| `progression.md` | Levels, tiers, brackets and stages; the pace each skill aims for; how quests and achievements carry a player across the world. | to write |
| `economy.md` | Resource flow: where every kind of thing enters the game (nodes, drops, shops, quests) and where it leaves (recipes, wear, fees, death), drawn as one diagram, so nothing piles up with no sink. | to write |
| `look-and-sound.md` | The art and audio direction in words: what R'th should look and sound like (the dark, weathered OSRS-style look, the interface's style), with links to the production rules that make it (`docs/assets.md`, `docs/interface.md`). | to write |

How they are used ([../rules.md](../rules.md) section 5): every feature, place and system names the
goal it serves; a proposal that serves no pillar, or works against one, says why it is still worth
having or is dropped.

**Sources:** `CLAUDE.md` (the opening and the architecture's reasons), `docs/systems.md` (design
principles), `docs/skills.md` 1-2, `docs/world-guide.md` 1, `docs/assets.md` 1, `docs/interface.md`
(look), `docs/areas/decisions.md`.
